# Contributing to API Learn

Thank you for helping improve **API Learn**.

API Learn is a public educational platform, while its source code is private. Because of this, contributions are mainly focused on bug reports, feedback, documentation issues, ideas, and discussions rather than source-code pull requests.

## How you can contribute

You can help by:

* reporting reproducible bugs
* reporting incorrect or unclear documentation
* suggesting new practice scenarios
* suggesting useful REST or SOAP operations
* reporting unexpected scraping or browser automation behavior
* sharing feedback about the learning experience
* participating in GitHub Discussions

## Reporting bugs

Please use the appropriate GitHub Issue template whenever possible.

A useful bug report should include:

* the URL or endpoint
* HTTP method, if applicable
* expected behavior
* actual behavior
* HTTP status code
* relevant request and response data
* minimal reproduction steps
* library, browser, or tool version when relevant

Please reduce examples to the smallest reproducible case.

## Questions and learning help

Questions about how to use the platform, REST API, SOAP, HTTP, scraping, or browser automation should usually go to **GitHub Discussions** rather than Issues.

Issues are intended for problems with the platform itself.

## Feature ideas

Ideas and suggestions are welcome.

Please describe:

* what you would like to practice
* why the scenario would be educationally useful
* which part of the platform it relates to
* a possible example of the expected behavior

## Pull requests

The application source code is private and is not published in this repository.

For that reason, source-code pull requests are generally not applicable.

Small improvements to public repository content, such as documentation files, may be considered.

## Security issues

Please do **not** report security vulnerabilities in public Issues or Discussions.

See [SECURITY.md](SECURITY.md) for responsible disclosure instructions.

## Sensitive data

Never publish:

* passwords
* access tokens
* JWTs
* cookies
* session IDs
* API credentials
* real personal information

API Learn is designed to work with fake educational data.

## Responsible use

API Learn is intentionally built for experimentation, but please do not intentionally overload, attack, or disrupt the service.

The goal is to learn how web applications, APIs, HTTP, scraping, and automation behave in realistic conditions.

Thank you for helping make API Learn better.
